1. ARCHITECTURE & SECURITY MODEL
================================================================================

CloudGuard GRC (Local/Host)                Target AWS Test Account
+----------------------------+             +-----------------------------------+
|  Scan Engine               |             |  IAM Role:                        |
|                            |             |  CloudGuardReadOnlyAuditRole      |
|  External ID               |  sts:       |                                   |
|  (e.g., cg-ext-9a8b7c)     |  AssumeRole |  Attached AWS Managed Policy:     |
|                            +------------>|  - SecurityAudit                  |
|  Validation Mode:          |             |  - ViewOnlyAccess                 |
|  Strict Read-Only Access   |             |                                   |
+----------------------------+             |  Audited Resources:               |
                                           |  S3, EC2, IAM, CloudTrail, KMS    |
                                           +-----------------------------------+

Key Security Guarantees:
- Agentless and 100% read-only.
- Never mutates, modifies, or deletes customer cloud infrastructure.
- Uses STS AssumeRole with External ID to eliminate the Confused Deputy vulnerability.
- Never stores or requests root keys, IAM user passwords, or long-lived secret keys.

2. PHASE 1: AWS TEST ACCOUNT PREPARATION
================================================================================

TIP: Always perform testing inside an isolated sandbox or AWS Free Tier account
rather than a shared production environment.

1. Sign in to the AWS Management Console:
   https://aws.amazon.com/console/

2. Find and copy your 12-Digit AWS Account ID:

   - Note down the 12-digit number (e.g., 123456789012).

3. PHASE 2: CREATE READ-ONLY IAM ROLE
================================================================================

CloudGuard GRC connects via STS AssumeRole using an External ID condition and
attaches the AWS-managed "SecurityAudit" policy.

--------------------------------------------------------------------------------
METHOD A: Using AWS Management Console (ClickOps)
--------------------------------------------------------------------------------

Step 1: Navigate to IAM Service
- Go to IAM > Roles > Click "Create role".

Step 2: Select Trusted Entity
- Trusted entity type: Select "AWS account".
- Account selection: Select "An AWS account" and enter your 12-digit Account ID.
- Under Options, CHECK "Require external ID".
- Enter the External ID generated by CloudGuard GRC (e.g., cg-ext-test-demo123).
- Leave "Require MFA" UNCHECKED (for automated auditor access).
- Click "Next".

Step 3: Add Permissions
- In the search bar, search for "SecurityAudit".
- Check the box next to "SecurityAudit" (Policy ARN: arn:aws:iam::aws:policy/SecurityAudit).
- Optional: Also search for and check "ViewOnlyAccess" for complete resource inventory.
- Click "Next".

Step 4: Name, Review, and Create
- Role name: CloudGuardReadOnlyAuditRole
- Role description: Read-only auditing role for CloudGuard GRC CSPM platform.
- Click "Create role".

Step 5: Copy the Role ARN
- Click on the newly created role name.
- Copy the Role ARN (Format: arn:aws:iam::<YOUR_ACCOUNT_ID>:role/CloudGuardReadOnlyAuditRole).


--------------------------------------------------------------------------------
METHOD B: Using AWS CLI (Scripted One-Click Setup)
--------------------------------------------------------------------------------

1. Create a local trust policy file named "trust-policy.json":
(Replace <YOUR_ACCOUNT_ID> and <YOUR_EXTERNAL_ID> with your actual values)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::<YOUR_ACCOUNT_ID>:root"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "<YOUR_EXTERNAL_ID>"
        }
      }
    }
  ]
}

2. Run the following AWS CLI commands to create and configure the role:

# A. Create the IAM Role
aws iam create-role \
  --role-name CloudGuardReadOnlyAuditRole \
  --assume-role-policy-document file://trust-policy.json \
  --description "Read-only auditing role for CloudGuard GRC CSPM"

# B. Attach SecurityAudit AWS Managed Policy
aws iam attach-role-policy \
  --role-name CloudGuardReadOnlyAuditRole \
  --policy-arn arn:aws:iam::aws:policy/SecurityAudit

# C. Attach ViewOnlyAccess AWS Managed Policy
aws iam attach-role-policy \
  --role-name CloudGuardReadOnlyAuditRole \
  --policy-arn arn:aws:iam::aws:policy/job-function/ViewOnlyAccess

# D. Verify role creation and output the ARN
aws iam get-role --role-name CloudGuardReadOnlyAuditRole --query "Role.Arn" --output text

4. PHASE 3: CREATE INTENTIONAL TEST FLAWS (DETECTION BENCHMARKS)
================================================================================

To verify CloudGuard GRC detection capabilities, provision these safe, zero-cost
test misconfigurations in your test account:

--------------------------------------------------------------------------------
Test Flaw 1: S3 Bucket without Public Access Block (CIS AWS 2.1.1)
--------------------------------------------------------------------------------
Creates an empty S3 bucket with public access block explicitly disabled:

aws s3api create-bucket \
  --bucket cloudguard-test-unprotected-bucket-<YOUR_ACCOUNT_ID> \
  --region us-east-1

aws s3api put-public-access-block \
  --bucket cloudguard-test-unprotected-bucket-<YOUR_ACCOUNT_ID> \
  --public-access-block-configuration "BlockPublicAcls=false,IgnorePublicAcls=false,BlockPublicPolicy=false,RestrictPublicBuckets=false"

--------------------------------------------------------------------------------
Test Flaw 2: EC2 Security Group with Open Port 22 SSH (CIS AWS 5.2)
--------------------------------------------------------------------------------
Creates a test security group allowing unrestricted inbound SSH (0.0.0.0/0):

# Get default VPC ID:
VPC_ID=$(aws ec2 describe-vpcs --filters "Name=isDefault,Values=true" --query "Vpcs[0].VpcId" --output text)

# Create Security Group:
SG_ID=$(aws ec2 create-security-group \
  --group-name "cloudguard-test-insecure-sg" \
  --description "Test security group with open SSH ingress" \
  --vpc-id $VPC_ID \
  --query "GroupId" --output text)

# Authorize unrestricted 0.0.0.0/0 ingress on Port 22:
aws ec2 authorize-security-group-ingress \
  --group-id $SG_ID \
  --protocol tcp \
  --port 22 \
  --cidr 0.0.0.0/0

--------------------------------------------------------------------------------
Test Flaw 3: IAM Policy with Wildcard Admin Action (CIS AWS 1.16)
--------------------------------------------------------------------------------
Creates an overly permissive test IAM policy containing wildcard statements:

cat <<EOF > test-wildcard-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowAllToAll",
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*"
    }
  ]
}
EOF

aws iam create-policy \
  --policy-name "CloudGuardTestWildcardAdminPolicy" \
  --policy-document file://test-wildcard-policy.json

5. PHASE 4: CONNECT ACCOUNT IN CLOUDGUARD GRC
================================================================================

1. Open your web browser and navigate to:
   http://localhost:5173

2. Log in to your CloudGuard GRC account (or register a new organization profile).

3. In the sidebar, click "Accounts" and then click "Connect New Account"
   (Direct URL: http://localhost:5173/accounts/onboard).

4. Step 1 (Select Provider):
   - Choose "AWS".

5. Step 2 (External ID):
   - Click "Copy ID" to copy the unique generated external ID (e.g. cg-ext-xxxxxxxxxx).
   - Ensure your IAM Role trust policy condition matches this External ID.

6. Step 3 (Role Details):
   - Account Alias: AWS-Test-Lab
   - AWS 12-Digit Account ID: <YOUR_12_DIGIT_ACCOUNT_ID> (e.g., 123456789012)
   - Read-Only IAM Role ARN: arn:aws:iam::<YOUR_ACCOUNT_ID>:role/CloudGuardReadOnlyAuditRole

7. Click "Verify & Connect Account".


================================================================================
6. PHASE 5: VERIFICATION & SCAN EXECUTION
================================================================================

1. Return to the Dashboard (http://localhost:5173/dashboard).
2. Click "Run On-Demand Scan" in the upper right header.
3. Wait for the progress indicator to complete (100%).
4. Navigate to "Findings Explorer" (http://localhost:5173/findings):
   - Confirm that the security flaws are detected:
     * RULE-AWS-002: S3 Public Access Block Disabled
     * RULE-AWS-003: Open Port 22 SSH on Security Group
     * RULE-AWS-007: Overly Permissive IAM Wildcard Admin Policy
   - Click "View Fix" on any finding to review copyable Terraform and AWS CLI fixes.
5. Navigate to "Compliance Matrix" (http://localhost:5173/compliance):
   - View posture evaluation scores against CIS AWS Foundations Benchmark, SOC 2, and DPDPA.
   - Click "Export Audit PDF" to download the executive HTML audit report.


================================================================================
7. PHASE 6: TEARDOWN & CLEANUP (ZERO CLOUD SPRAWL)
================================================================================

When testing is complete, run the following commands to delete all test resources
and prevent any unwanted AWS cloud sprawl:

# 1. Detach and Delete IAM Test Role & Policy:
aws iam detach-role-policy --role-name CloudGuardReadOnlyAuditRole --policy-arn arn:aws:iam::aws:policy/SecurityAudit
aws iam detach-role-policy --role-name CloudGuardReadOnlyAuditRole --policy-arn arn:aws:iam::aws:policy/job-function/ViewOnlyAccess
aws iam delete-role --role-name CloudGuardReadOnlyAuditRole
aws iam delete-policy --policy-arn arn:aws:iam::<YOUR_ACCOUNT_ID>:policy/CloudGuardTestWildcardAdminPolicy

# 2. Delete the Test Security Group:
aws ec2 delete-security-group --group-id $SG_ID

# 3. Delete the Test S3 Bucket:
aws s3 rb s3://cloudguard-test-unprotected-bucket-<YOUR_ACCOUNT_ID> --force

# 4. Remove local temporary policy files:
rm -f trust-policy.json test-wildcard-policy.json
